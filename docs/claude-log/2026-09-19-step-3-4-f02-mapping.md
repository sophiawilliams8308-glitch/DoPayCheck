## Decisions

- Chose runtime `Object.freeze` on both the top-level map and each per-capability array,
  slightly beyond the type-level-only convention used by adjacent Step 1/2 constants
  (`CAPABILITY_PROGRAM`, `ALL_STATE_RULE_KEYS`), because this mapping will be consumed by
  future rule-selection code where a caller mutating a shared array would corrupt it for every
  subsequent lookup — a materially higher-stakes shared structure than a read-only vocabulary
  list.
- Did not add a runtime validation branch for an out-of-vocabulary capability value, matching
  `consultCoverage`'s (Step 3.3) own precedent of trusting the `CapabilityCode` type boundary
  rather than introducing a second, inconsistent runtime-validation convention for the same
  vocabulary.
